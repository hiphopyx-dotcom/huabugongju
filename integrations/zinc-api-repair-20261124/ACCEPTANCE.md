# 留给父线程的真实验收

本包的 17 项测试都是隔离 mock。它们不能代替下面的现站操作。本代理没有登录、没有读密钥、没有向现站或付费接口发写请求，也没有发布。

在 Grok 项目里 apply 成功并且有人把补丁装进预览之后，再用已经保存过配置的浏览器验收。装上之前，现站行为不变。

## 文字

1. 使用浏览器里已经保存的 Agnes 国际版配置，在剧本创作或拆镜提交一句很短的要求。
2. 通过条件是响应里有非空正文，并且请求主机是该配置的 Base URL。
3. 清掉本机自定义模型后再提交。页面应出现「未配置自定义模型」，网络面板里没有 `api.x.ai`。
4. 把 Base URL 改成 `https://api.x.ai/v1` 或 `https://api.x.ai.evil.com/v1` 时，保存或提交应被拒绝，并且没有出站请求。

## 图片和视频

1. 空的 `POST /api/images?action=generate` 应是 400「没有画面要求」，不再是 500 `HTTPError`。
2. 无 id 的 `GET /api/pianchang-video` 应是 400「没有这条任务」。
3. 只有当前出图方式不是正在被导演使用的 Grok 会员队列时，才各做一次图片和视频。通过条件是任务进入终态后能取到 `dataUrl` 或 `https` `url`。`queued:true` 或 HTTP 200 不算通过。
4. 不要改全站 choice，不要把测试任务送进生产 Grok 会员队列。

## 云端冲突

1. 不要对第 0/15 集、昭雪、桂花点云保存，也不要删库。
2. 两个会员浏览器编辑同一项目时，后保存的一方应看到冲突，并且下一次自动保存不再上传。云端正文保持先保存的那一版。
3. `cloudRevision` 只是数字。新工程没点过「上传到云端」也可能因为自动保存或旧的 409 处理带上 4。用项目 id、剧本正文和云端文档对照，不用这个字段当成功证明。

## 403

补齐 method、action 和响应 JSON 之后，再对照 `bench-members-403.md`。现有的孤立 403 发生在新建之前，先不要归因到新工程，也不要把它写成整段认证失效。
